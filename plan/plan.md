# SoundTrack：应用音频路由与 OBS 插件

## 概要

技术栈确定为 **Rust + Tauri 2 + Vue 3 + TypeScript + Tailwind CSS**。Vue 使用 Composition API 和 `<script setup lang="ts">`，前端通过 Vite 构建，使用 pnpm 管理依赖。

目标支持 Windows 10 22H2 x64、Windows 11 x64，捕获能力须通过原型实机验证。后台捕获应用音频，混合为 Game、Media、Voice 三路，通过配套 OBS 插件提供独立音频源。任何未被路由配置且正在发出声音的应用程序默认自动路由到 Game，无需逐个手动添加。无需虚拟设备或路由窗口；关闭配置窗口后驻留托盘。应用原声保持正常播放，滑条仅调整 OBS 音频副本。

## 音频与匹配

- 使用 Rust 调用 WASAPI Process Loopback，启动时实际检测捕获能力。Microsoft 文档的最低版本为 Build 20348，与 Windows 10 22H2 的支持目标存在差异；先验证目标系统实际可用性，再确认支持范围，不仅按版本号推断兼容性。无法捕获时明确显示原因。
- 固定三个路由，同一应用及其多个实例归属同一路由。
- 持久化可执行文件完整路径、文件名、窗口标题、窗口类和匹配模式；默认在相同路径候选中优先匹配标题，再回退到路径匹配。文件名回退由用户开启。
- 路由优先级为：排除项 → 用户显式规则 → 默认 Game。匹配到 Media、Voice 或 Game 显式规则的应用只进入对应分组；分组静音或音量为 0 时仍保留归属，不回退到 Game。显式规则冲突时显示冲突，不用默认 Game 掩盖冲突。
- 启动时枚举所有活动播放设备的现有音频会话，运行期间监听会话创建、状态变化及设备变化，持续发现未配置的发声应用，包括无可见窗口的后台应用；不能只枚举窗口或启动时扫描一次。使用会话关联 PID 定位应用，按应用身份合并多个会话和实例。
- 未配置应用开始播放时自动进入 Game，使用 Game 的增益和静音设置；短暂静音不反复移除或重建捕获，播放恢复后继续路由。进程退出或会话失效后清理自动项，重启后重新发现。自动项仅存在于运行时，不写入持久化匹配规则。
- 用户将自动项移动到任一分组（包括固定到 Game）时保存显式规则并即时更新归属；删除显式规则表示恢复默认路由，仍在发声的应用重新进入 Game，不表示排除录音。
- PID 仅用于运行时。应用退出后保留规则并显示离线，重新启动后自动恢复捕获。
- 同路重叠进程树去重。Process Loopback 捕获目标进程及其子进程，已被显式捕获树覆盖的子进程不能另建自动 Game 捕获。两条显式规则跨路重叠时报告冲突并暂停冲突项；自动 Game 候选不能导致显式规则暂停，也不能把 Media/Voice 已覆盖的声音再次混入 Game。原型必须验证未配置父进程与显式配置子进程同时发声的情况，确认能保持默认 Game 覆盖且不串音；若进程树粒度无法满足，须先调整捕获方案，不能通过漏录未配置应用绕过需求。排除 SoundTrack、OBS 及其子进程，防止回授。
- 内部统一为 48 kHz、双声道、Float32，按时间戳对齐后混音，处理必要的重采样和格式转换。
- 音量范围 0–100%，默认 50% 为线性增益 0.5；平滑调节，混音后限幅并显示过载。
- 使用有界音频队列，缺帧补静音，积压丢弃过期数据。音频线程不执行配置读写或界面通信。
- 首版不包含麦克风采集，也不支持浏览器标签页独立分流。

## OBS 插件与通信

- 插件采用 Rust `cdylib`，使用官方头文件生成 libobs C ABI 绑定，导出 OBS 必需的模块入口，在 `obs_module_load` 中调用 `obs_register_source` 注册音频输入源（`OBS_SOURCE_TYPE_INPUT`、`OBS_SOURCE_AUDIO`）。
- 注册 `soundtrack_route_audio` 音频源，显示名称为「SoundTrack 路由音频」，属性 `route` 可选择 `game`、`media`、`voice`。
- 用户按下述流程添加三个源并分配 OBS 录制音轨，不自动修改已有场景。SoundTrack 负责捕获、分组和混音，插件负责向 OBS 提供三路音频，OBS 负责画面捕获、编码与录制文件。
- 使用限定当前 Windows 用户访问的命名管道。协议 v1 包含版本握手、路由订阅，以及序号、帧数、QPC 时间戳和音频数据。
- 插件将时间戳映射到 OBS 单调时钟，通过 `obs_source_output_audio` 提交音频；同路多个源共享接收连接并分发。
- 支持任意启动顺序、断线静音和自动重连；恢复时丢弃旧缓冲，协议不兼容时明确提示。
- 首版固定实施时官方最新稳定版 OBS Windows x64 及对应 SDK，不承诺跨版本二进制兼容。

## OBS 录制接入流程

1. 安装与目标 OBS 版本匹配的 SoundTrack 插件并重启 OBS；启动 SoundTrack，确认捕获可用。未配置的发声应用自动出现在 Game，需要分流的应用显式移到 Media 或 Voice。
2. 在 OBS 场景中添加三个「SoundTrack 路由音频」源，分别命名为 Game、Media、Voice，属性 `route` 对应选择 `game`、`media`、`voice`。需要多场景复用时添加已有源，避免同一场景重复添加同一路音源。
3. OBS「设置 → 音频」采样率设为 48 kHz，禁用全局桌面音频（包括第二桌面音频）；不再同时捕获这些应用的「应用音频捕获」或「音频输出捕获」。游戏/窗口捕获仍用于画面，但关闭其音频捕获选项。三个 SoundTrack 源的音频监听均设为关闭，避免已经正常播放的原声再经 OBS 重复监听。
4. 在 OBS「高级音频属性」按下表勾选音轨。三个源的 OBS 音量初始设为 0 dB，通过 SoundTrack 调整各路增益。

   | OBS 音源 | 音轨 1：完整混音 | 音轨 2：Game | 音轨 3：Media | 音轨 4：Voice |
   | --- | --- | --- | --- | --- |
   | Game | ✓ | ✓ | — | — |
   | Media | ✓ | — | ✓ | — |
   | Voice | ✓ | — | — | ✓ |

5. 在 OBS「设置 → 输出」切换到高级模式，在「录制」中选择 MKV 并启用音轨 1–4；按需配置视频源和编码器，开始录制。普通播放器一次通常只播放一个音轨，第 1 轨保留完整混音，第 2–4 轨供后期分别处理。需要 MP4 时使用 OBS「文件 → 录像转封装」。
6. 若需录制麦克风，在 OBS 中另加麦克风源，分配到混音轨 1 和独立轨 5，并在录制设置中额外启用轨 5；Voice 在首版仅代表应用语音，不包含麦克风采集。

音轨设置依据 [OBS 多音轨录制指南](https://obsproject.com/kb/multiple-audio-track-recording-guide)，格式依据 [OBS 录制输出指南](https://obsproject.com/kb/standard-recording-output-guide)。关闭重复采集参考 [OBS 应用音频捕获指南](https://obsproject.com/kb/application-audio-capture-guide)，同样适用于 SoundTrack 三路源与桌面音频同时录入的情况。

## Vue 界面与配置

- 使用 Vue 3 单文件组件和 Tailwind CSS，实现中文深色调音台。Game、Media、Voice 三张卡片分别使用蓝、紫、绿强调色，窄窗口纵向排列。
- 每路包含应用列表、增删与移动操作、匹配模式、在线状态、实时电平、音量滑条和静音按钮。
- Game 列表区分「自动」应用和显式规则；自动项支持移动或保存为显式规则，删除规则操作提示「恢复默认 Game」。显式离线规则继续保留，自动项退出后移除。
- 应用选择器支持搜索运行中的应用，也支持选择可执行文件添加离线规则。
- 顶部显示捕获状态、OBS 连接状态，并提供上述插件接入、音轨分配和避免重复录音的简短指引。
- 使用 Vue 响应式状态与 composable 管理配置和运行状态，首版不引入 Vue Router 或独立状态管理库。
- Tauri 命令负责配置读取、应用枚举、规则更新和路由增益；事件推送状态与电平，音频数据不经过前端。
- 配置保存至 `%APPDATA%\SoundTrack\config.json`，包含版本、路由、音量、静音和用户显式匹配规则；默认未配置应用路由到 Game 为固定行为，自动发现项不写入配置。原子写入、即时生效。
- 主程序单实例，关闭窗口进入托盘；托盘提供打开设置和完全退出，默认不开机自启。

## 实施与验收

1. 先完成单应用捕获 → IPC → OBS 插件原型，验证两个目标 Windows 系统的实际捕获能力、后台完全隐藏、耳机原声不变和 OBS 独立收音；同时验证进程树重叠下显式路由与默认 Game 的隔离，再确定捕获方案。参考 [Microsoft 应用 Loopback 示例](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/) 和 [Process Loopback 模式](https://learn.microsoft.com/en-us/windows/win32/api/audioclientactivationparams/ne-audioclientactivationparams-process_loopback_mode)。
2. 实现音频会话动态发现、默认 Game、显式规则优先、三路混音、应用匹配、去重、持久化及恢复机制。
3. 完成 Vue 界面，交付 Windows x64 应用安装包、OBS 插件包及 PowerShell 7 安装/卸载脚本。

验收包括：

- Windows 10 22H2、Windows 11 实机与固定 OBS 版本。
- 三路不同测试信号无串音，同路多应用正确混合。
- 按 OBS 接入流程录制，文件包含音轨 1–4；第 1 轨包含完整混音，第 2–4 轨分别只有 Game、Media、Voice。确认桌面音频、应用捕获和监听不会造成重复录音；按需验证独立麦克风轨。
- 在 SoundTrack 启动前已经发声、运行期间开始发声及无窗口的未配置应用均自动进入 Game；覆盖多播放设备、设备切换、短暂静音后恢复、进程重启和多个音频会话，检查发现与捕获启动期间的漏音并记录耗时。
- 将自动应用移动到 Media/Voice 后 Game 不再收录其音频；配置重启后保留，删除规则后回到 Game。显式分组静音或音量为 0 不触发 Game 回退，自动项不污染配置文件。
- 默认 50% 约为 −6.02 dB，音量及静音不影响耳机原声。
- 应用重启、标题变化、多实例、路径回退、离线规则及进程树冲突；已配置树中的新子进程不重复进入 Game，同路父子不重复录音，未配置父进程与显式配置子进程同时发声时无漏录、无跨路串音。
- OBS/后台重启、休眠恢复、设备切换、通信积压及协议错误。
- 连续录制两小时，检查爆音、音画偏移、资源泄漏和延迟增长；正常负载新增延迟目标不超过 100 ms。
- 自动测试覆盖匹配、默认 Game 与显式规则优先级、会话生命周期、去重、配置、混音和 IPC；前端完成类型检查、生产构建及实际窗口尺寸下的交互验证。
